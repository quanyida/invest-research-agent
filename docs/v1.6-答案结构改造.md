# v1.6 答案结构改造（对齐 Alpha派 / AlphaEngine）

日期：2026-11-18
状态：已实现并通过验证

## 1. 背景

对标 Alpha派（讯兔科技）与 AlphaEngine（熵简科技）的答案形态：

- Alpha派：以「交付物」为中心，模板化、图表化，一次成稿。
- AlphaEngine：以「证据链」为中心，判断先行、推理可展开、句级引用可回溯、明示证据缺口与机构分歧。

v1.5 的答案是纯文本四段（结论/关键数字/正文/边界），存在三个差距：

1. 引用只以 `[E1-1]` 形式留在行内，没有独立的来源区块，用户无法回看原文。
2. 「边界」把口径、缺失项、机构分歧混在一段。
3. 所有问题都套用同一骨架，公司/行业研究缺少可交付的文档结构。

## 2. 改动

### 2.1 提示词（`app/agent/context.py`）

四段骨架保持不变，新增三类约束：

- 长度分档：指标类 ≤ 400 字；公司研究/行业研究/业绩点评 ≤ 1200 字。
- 边界固定两行：`口径与缺失：` 与 `分歧：`；无多机构观点时写「未取到多机构观点」。
- 任务型模板骨架（写在「正文」内部，小标题独占一行、以「：」结尾、不编号）：
  - 公司研究：核心逻辑 / 业务与财务 / 驱动与催化 / 可比与估值 / 跟踪指标
  - 行业研究：行业全景 / 商业模式 / 政策环境 / 产业链 / 空间测算 / 竞争格局 / 核心标的
  - 空间测算必须写清「假设 + 公式 + 结果」，无证据支撑的假设标注「假设值」。

修复提示同步改为「边界只写两行：口径与缺失 / 分歧」。

### 2.2 渲染（`static/assets/app.js`）

- 解析四段，分块渲染；流式阶段仍用纯文本，`done` 时切换为结构化视图。
- 「正文」识别小标题行，渲染为二级标题。
- 「边界」拆成「口径与缺失 / 分歧」两行。
- 新增「来源」区块：从答案中按出现顺序提取 `[E1-n]`，与证据 facts 关联，生成来源卡（实体 · 期间 · 指标 · 数值 · 工具）。
- 点击来源卡 → 右侧证据面板定位到对应 fact 并高亮。

### 2.3 样式（`static/assets/app.css`）

新增分块、二级标题、边界两行、来源卡、fact 高亮动画。

### 2.4 测试（`tests/test_answer_format_prompt.py`）

5 个用例：边界子标签、两套模板骨架、Agent 提示词包含模板与两行边界、修复提示词、两行边界仍通过校验。

## 3. 影响面与不变项

- SSE 事件名未变：`meta/plan/tool_start/tool_end/evidence/verify/delta/usage/done`。
- `AGENT_ENGINE=legacy` 回滚链路未改动。
- 校验硬规则未变：四段标签 + fact 级引用 + 数字一致性。
- 未引入新依赖，未改数据库结构。
