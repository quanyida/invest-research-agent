# v1.6.1 模型超时兜底

日期：2026-11-18
状态：已实现并通过验证

## 1. 问题与根因

用户提问「深度分析下安克创新的业务情况和AI时代下的预期」时，请求失败。

根因是模型 SDK 抛出的 `openai.APITimeoutError` 没有被运行时捕获：

- 原代码只捕获内建 `TimeoutError` 和任务级 `asyncio.timeout`。
- `APITimeoutError` 不属于内建 `TimeoutError`，异常直接冒泡到 SSE 层，前端只看到 `error`。
- 同时 `LLM_TIMEOUT_SECONDS=60`、`TASK_TIMEOUT_SECONDS=180`，对包含多轮工具调用的深度研究问题偏紧。

## 2. 改动

### 2.1 AgentScope 运行时（`app/agent/agentscope_runtime.py`）

- 引入 `openai.APITimeoutError`。
- 新增 `_timeout_fallback(...)`：超时后使用已收集证据生成四段式摘要，而不是直接失败。
- 捕获 `(TimeoutError, APITimeoutError)`，并区分两类超时：
  - 模型调用超时：`answer_source=model_timeout`，trace 状态 `MODEL_TIMEOUT`。
  - 整轮任务超时：`answer_source=timeout`，trace 状态 `TIMEOUT`。
- 在 `meta` 写入 `timeout=true`；模型超时时额外写入 `model_timeout=true`。
- 降级回答仍保留 fact 引用，正文不写超时秒数，秒数只放在 trace/meta，避免被事实校验当成无引用数字。

### 2.2 配置（`.env`）

- `LLM_TIMEOUT_SECONDS`：`60` -> `120`
- `TASK_TIMEOUT_SECONDS`：`180` -> `300`
- `LLM_MAX_TOKENS`：保持 `2048`

### 2.3 测试（`tests/test_timeout_fallback.py`）

新增两个用例：

- 模型超时：返回 `model_timeout` / `MODEL_TIMEOUT`，生成的摘要可通过 `verify_answer`。
- 任务超时：返回 `timeout` / `TIMEOUT`，生成的摘要可通过 `verify_answer`。

## 3. 降级行为

超时后仍返回正常的 SSE 链路：

`meta/plan/tool_start/tool_end/evidence/verify/delta/usage/done`

差异只在语义字段：

- `status=degraded`
- `degraded=true`
- `verify.passed=false`
- `verify.issues=["model_timeout"]` 或 `["timeout"]`
- `answer_source` 对应为 `model_timeout` 或 `timeout`

正文是基于已取回证据的四段式摘要，用户可以继续阅读和回溯引用；前端也能通过 `verify/meta` 明确知道本轮是降级结果。
